=== 학년도별 입학 일정 조회

`GET /admin/schedules?admission-year={year}`로 보관된 학년도별 일정을 조회합니다.

=== 새로운 학년도 일정 생성

`POST /admin/schedules`로 새로운 학년도 일정을 생성하고 활성 일정으로 전환합니다.
기존 활성 일정은 이력으로 보관됩니다.

사용합니다. 생성 요청에서는 `version`을 생략하고, 수정 요청에서는 현재 일정 조회

=== 현재 입학 일정 수정

어드민은 `PUT /admin/schedules/current`로 현재 일정을 수정할 수 있습니다.
조회 응답의 `version`을 요청에 포함해야 하며, 다른 관리자가 먼저 수정한 경우
`409 Conflict`가 반환됩니다.

일정은 원서 접수, 1차 선발과 발표, 전형, 최종 발표, 등록 및 서약서 제출

=== 운영 동작

일정의 시간대는 `Asia/Seoul`입니다. 1차 합격자 예약 자동 선발은 폐기되었습니다.
서버 시작, 일정 수정, `selectFirstPassAt` 도달만으로 선발하지 않습니다.
관리자가 `PATCH /admin/forms/first-round/select`를 호출해야 현재 일정의 선발이 실행됩니다.
`selectFirstPassAt`은 기존 API/DB 호환성을 위해 유지하는 계획 시각이며 실행 트리거가 아닙니다.
수동 실행은 이 계획 시각까지 기다리지 않으므로 관리자는 접수·검토 완료를 확인한 뒤 호출해야 합니다.
이미 선발이 실행된 일정의 계획 시각은 변경할 수 없으며, 일정별 1차 선발은 한 번만 실행됩니다.

일정 생성 및 수정 시 관리자, IP, User-Agent, 변경 전후 값이 변경 이력에
기록됩니다.

=== PDF 학년도와 최초 설정

입학원서, 검정고시 입학원서, 특례입학원서, 입학등록원의 제목과 본문은
현재 활성 일정의 `admissionYear`를 사용합니다. 어드민이 학년도를 수정하면
그 이후 새로 생성하는 PDF에 반영됩니다. 수험표와 접수증의 전형 일정도
현재 활성 일정을 참조합니다.

서약서 등의 작성일은 실제 PDF 생성일이며, 입학 학년도나 접수 시작일로
대체하지 않습니다. 이미 S3에 제출된 PDF와 해당 파일을 병합한 출력물은
재생성하지 않으므로 기존 내용이 유지됩니다.

일정이 전혀 없는 새 환경에서는 과거 학년도 일정을 자동 생성하지 않습니다.
관리자가 `POST /admin/schedules`로 확정된 일정을 먼저 등록해야 합니다.
등록 전 현재 일정 조회와 수동 선발은 `404 SCHEDULE_NOT_FOUND`를 반환합니다.
기존 활성 일정이 있으면 그대로 유지하며, 활성 일정 없이 보관 일정만
존재하면 가장 최신 학년도의 일정을 활성화합니다.
