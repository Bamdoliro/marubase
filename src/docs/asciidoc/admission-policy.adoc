== 입학 정책 (교사 검토용 초안)

=== 적용 범위

이 API는 백엔드 기능이다. 관리자 화면은 별도 구현해야 한다.

* 실제 반영: 전형별 정원, 1차 선발 배수, 타지역 비율, 수험표 안내문.
* 미리보기만 제공: 점수식 DSL. 기존 `CalculateFormScoreService`는 바뀌지 않으며
  학생 점수/합격 상태/문자/저장된 PDF를 변경하지 않는다.
* 점수 배점, F 대체/제외 규칙, 검정고시 환산표, 자격증 중복 처리, 동점자 처리 등의
  모든 하드코딩을 제거한 버전은 아니다. 원시 과목 기반 DSL 미리보기는 제공하지만 운영 성적 DB 연결은 후속 범위다.

배포 전 PostgreSQL에 `scripts/add-admission-policy.sql`을 실행한다.
기존 일정에 정책 행이 없으면 기존 기본값을 읽는다. GET은 DB를 변경하지 않는다.
첫 수정 또는 선발 때 정책 행을 저장한다. 일정 ID에 연결하므로 학년도 이름을 바꿔도 정책은 유지된다.
새 일정은 기존 정책을 복사하지 않고 기존 기본값에서 시작한다.

=== 관리자 API

아래 엔드포인트는 모두 ADMIN 액세스 토큰 쿠키 인증이 필요하다.
비인증/일반 사용자에 대한 응답은 기존 관리자 인증 규칙을 따른다.

[cols="1,3,4"]
|===
|메서드 |경로 |용도
|GET |/admin/admission-policies/current |현재 일정의 정책
|GET |/admin/admission-policies?admission-year=2027 |특정 학년도 정책
|PUT |/admin/admission-policies/current |현재 일정의 전체 정책 교체
|GET |/admin/admission-policies/history?admission-year=2027 |최근 변경 이력 50개 (최신순)
|POST |/admin/admission-policies/score-preview |점수식 검증 및 샘플 계산 (저장 없음)
|===

정책 조회/수정은 기존 CommonResponse의 `data`에 아래 값을 반환한다.
이력은 `dataList`에 `id, userId, createdAt, beforePolicy, afterPolicy`를 반환한다.
전후 정책은 JSON 문자열이며 수정자 ID와 함께 같은 트랜잭션에 저장한다.

[source,json]
----

  "admissionYear": 2027,
  "version": -1,
  "selectionLocked": true,
  "selection": {
    "regular": 48,

PUT 본문에는 조회한 `scheduleId, version, selection, ticket`만 보낸다.
생략 필드를 부분 수정으로 취급하지 않는다. 최초 미저장 버전은 -1이고 저장 후 0부터 증가한다.
활성 일정이 바뀌거나 버전이 오래되면 409 `POLICY_VERSION_CONFLICT`다.
응답 버전은 다음 수정에 사용한다.

==== 선발 정책 보호

* 각 정원: 0~1000 정수. 일반+마이스터+사회통합의 합계는 1~1000.
  정원 외 두 전형은 합계에 포함하지 않는다 (기존 동작).
* 배수: 1~5. 타지역 비율: 0~1.
* 한국 시간 기준 접수 시작 이후, 원서가 하나라도 존재하거나 선발에 사용한 정책은 정원 수정 불가.
  409 `SELECTION_POLICY_LOCKED`를 반환한다. 동일 정원을 유지한 안내문 수정은 가능하다.
* 현재 원서에는 학년도 귀속이 없어 원서 존재 검사는 전체 원서 대상이다.
  따라서 이전 학년도 원서가 남아 있으면 새 일정 정원도 편집이 제한된다.
  과거 데이터를 지워 우회하지 말고, 후속 원서-학년도 귀속 설계 후 이 제한을 좁혀야 한다.
* 첫 선발 시 잠금이 영구 저장된다. 일정 시간을 뒤로 변경해도 잠금은 해제되지 않는다.
* 선발과 정책 수정은 동일 일정 행을 잠근다. 중도에 정책 일부만 바뀐 결과를 만들지 않는다.
* 사회통합 하위 분배/미달 이월/동점자/특별전형 탈락자 전환 알고리즘은 기존 그대로다.
* 1차 타지역 정원: floor(ceil(정원합계 × 배수) × 비율).
  2차 타지역 정원: ceil(정원합계 × 비율).
* 정책 조회 불가/손상 시 선발을 실패시킨다. 저장된 정책 오류를 기본값으로 숨기지 않는다.

==== 수험표 문구

장소 3개는 각 40자, 예비소집/등록 방법은 80자, 점심/필수/금지 품목은 120자,
허용 품목은 180자까지이며 공백만으로 입력할 수 없다.
HTML을 허용하지 않고 이스케이프하여 표시한다.
개별/전체 수험표에 동일하게 적용한다. 전체 출력은 한 번 읽은 안내문을 모든 학생에 사용한다.
이미 다운로드했거나 S3에 저장된 문서는 바뀌지 않는다. 새로 생성하는 수험표부터 반영된다.
긴 문구는 PDF 페이지 수를 늘릴 수 있으므로 실제 출력 확인 후 운영값을 확정한다.

=== 점수식 미리보기 v1 (과목 원자료 지원)

[source,json]
----
{
  "source": "매개변수 기본점수 = 77.5\n계산 교과 = 기본점수 + 4.8 * (학기21 + 학기22) + 14.4 * 학기31 + 정보 / 2\n출력 점수 = 반올림(교과, 3)",
  "inputs": { "학기21": 5, "학기22": 5, "학기31": 5, "정보": 5 }
}
----

응답 `data`:

[source,json]
----
{
  "valid": true,
  "outputs": { "점수": 200.000 },
  "trace": { "기본점수": 77.5, "교과": 200, "점수": 200.000 },
  "error": null
}
----

문법/계산 오류는 HTTP 200, `valid: false`, 빈 outputs/trace와 한글 error로 반환한다.
본문 필수 필드 누락/길이 위반/잘못된 JSON은 기존 요청 검증대로 HTTP 400이다.
실패한 식의 일부 계산 결과를 정상 결과로 반환하지 않는다.

==== 현재 문법

[source,text]
----
프로그램 = 정의를 줄바꿈으로 구분
정의     = ("매개변수" | "계산" | "출력") 이름 "=" 식
이름     = 한글/영문 등 문자 또는 "_"로 시작, 이후 문자/숫자/"_"
식       = 숫자 | 문자열 | 없음 | 이름 | "(" 식 ")" | 단항연산 식 | 식 이항연산 식 | 함수
주석     = 문자열 밖의 "#"부터 줄 끝까지
----

* inputs는 기존 숫자 맵이다. subjects에 과목 원자료를 추가할 수 있다. 학생 ID로 DB를 조회하지 않는다.
* 괄호 안에서는 여러 줄로 식을 쓸 수 있다. 문자열은 큰따옴표로 감싸고 최대 80자다.
* 과목들과 없음은 예약어다. 출력은 숫자만 반환하고 계산은 숫자/문자열/과목 목록을 저장할 수 있다.
* 이름은 앞에서 정의한 것만 참조한다. 중복 이름/입력 덮어쓰기/순환/전방 참조는 거부한다.
* 숫자는 부호 없는 십진 리터럴로 적고 음수는 단항 `-`를 쓴다.
* 우선순위 (낮음 → 높음): `||`, `&&`, `== !=`, `< <= > >=`, `+ -`, `* /`, 단항 `+ - !`.
* 비교 결과는 1/0이고, 조건에서 0은 거짓, 그 외는 참이다.
* 함수: `조건(식, 참일때, 거짓일때)`, `최소(a,b)`, `최대(a,b)`,
  `반올림(값, 자리수)`, `내림(값)`, `올림(값)`, `절사(값)`, `절댓값(값)`.
* 조건/논리식은 단락 평가한다. 선택되지 않은 분기와 빈 목록의 행 식도 문법/이름/타입을 검증한다.
  조건의 두 결과 타입은 같아야 한다. 실행하지 않는 분기의 0 나눗셈 등 값 오류는 평가하지 않는다.
* BigDecimal 사용. 덧셈/뺄셈은 정확하게, 곱셈/나눗셈은 소수 12자리 HALF_UP.
  반올림도 HALF_UP (음수 중간값은 0에서 멀어짐).
  내림은 음의 무한대, 올림은 양의 무한대, 절사는 0 방향이다.
* `0`, 누락은 다르다. 누락/0으로 나누기는 오류다.
  F/미이수/해당 없음/원시 과목 목록을 숫자 0으로 자동 변환하지 않는다.
* 한도: 소스 8192자, 입력 40개, 정의 64개, 이름 40자, 토큰 2048개,
  중첩/연산 연쇄 32단계, 평가 연산 50000회, 숫자 절댓값 10^12 및 소수 12자리 이하.
* 반복/재귀/임의 함수/객체 속성/파일/네트워크/Java 호출 불가.
* 과목은 240개, 함수 인자는 32개, trace에 저장되는 과목 행은 전체 정의 합계 2048개까지다.
  중첩 집계도 동일 연산 예산을 공유한다. 한도 초과 시 부분 결과 없이 실패한다.
* 사용자 정의 함수/반복문/일반 객체 수정/정책 저장·게시/실점수 재산정은 아직 미지원이다.


==== 과목 원자료 요청

기존 요청의 subjects 생략/null은 빈 목록으로 처리하므로 숫자 수식 API는 유지된다.
복사해서 사용할 전체 요청은 examples/score-policy/subject-preview-request.json에 있다.

[source,json]
----
{
  "id": "math-2-1",
  "grade": 2,
  "semester": 1,
  "name": "수학",
  "achievement": "F",
  "originalScore": null
}
----

* id/name: 공백뿐이 아닌 1~40자, 제어문자 불가. id는 요청 안에서 고유해야 한다.
  id가 다르면 같은 이름의 행도 따로 집계한다. 자동 중복제거를 하지 않는다.
* grade/semester: 함께 생략(null)하거나 학년 1~3, 학기 1~2를 함께 지정한다.
  검정고시는 학년/학기를 생략한다 (0을 보내지 않는다).
* achievement: A~F 또는 null. 소문자는 자동 변환하지 않는다.
* originalScore: 0~100, 소수 4자리 이하 또는 null.
* achievement/originalScore 중 적어도 하나는 있어야 한다.
  둘 다 주면 모두 보존하며 어떤 값을 사용할지는 정책 코드에서 정한다.
* name은 정확한 문자열로 비교한다. 공백/동의어/과목코드를 자동 정규화하지 않는다.
* HTTP Bean Validation은 형식/범위 오류를 400으로, 중복 ID/학기 쌍/성적 둘 다 누락 같은
  도메인 검증은 200의 valid=false로 보고한다.

==== 과목을 처리하는 코드

[source,text]
----
# 2학년 1학기에서 국영수 F는 남기고, 다른 과목 F는 제외한다.
계산 대상 = 선택(과목들,
    학년 == 2 && 학기 == 1
    && (성취 != "F" || 포함(과목명, "국어", "영어", "수학"))
)
계산 대체 = 성취변경(대상, 조건(성취 == "F", "C", 성취))
계산 환산 = 점수화(대체,
    대응(성취, "A", 5, "B", 4, "C", 3, "D", 2, "E", 1),
    조건(과목명 == "수학", 2, 1)
)
출력 교과평균 = 조건(개수(환산) == 0, 0, 가중평균(환산, 점수, 가중치))
출력 반영과목수 = 개수(환산)
출력 가중분모 = 합계(환산, 가중치)
----

위 코드는 포함 과목 수와 가중 분모를 따로 반환한다.
수학 F, 국어 A, 과학 F를 보내면 수학은 C로 대체하고 과학은 제외하여
(3×2 + 5×1) / 3 = 3.666666666667을 반환한다.
분모는 과목 수 2가 아니라 가중치 합 3이다.

==== 행 필드와 범위

선택/성취변경/점수화/합계/평균/가중평균의 두 번째 이후 인자 식은 각 과목 행에서 평가한다.

* 학년, 학기, 원점수: 원본 값. 없으면 없음.
* 과목명: 원본 name.
* 원성취: 원본 achievement. 후속 변환으로 바뀌지 않는다.
* 성취: 현재 파생 성취도. 초기에는 원성취와 같고 성취변경 후에는 변환 결과.
* 점수, 가중치: 점수화로 만든 파생 숫자. 아직 만들지 않았다면 없음.

행 필드는 그 행의 식 안에서만 자동 제공한다. 전역에 같은 이름의 숫자 입력이 있으면
행 식 안에서는 행 필드가 우선하고 바깥에서는 전역 값을 쓴다.
집계를 중첩하면 가장 안쪽 과목이 현재 행이다. 바깥 행 참조 문법은 없다.

있음(원점수)는 누락 여부를 1/0으로 반환한다. 원점수 == 없음으로도 검사할 수 있다.
누락은 0이나 F와 같지 않으며 숫자 연산에 쓰면 오류다.
조건(있음(원점수), 원점수, 0)처럼 대체 규칙을 명시해야 한다.

==== 목록 변환과 집계

* 선택(목록, 조건식): 조건이 참인 행만 새 목록에 보존한다. 제외 행은 후속 분모에도 들어가지 않는다.
* 성취변경(목록, 성취식): A~F 문자열로 파생 성취를 만든다. 원본은 보존한다.
  성취를 다시 바꾸면 기존 점수/가중치는 폐기되므로 다시 점수화해야 한다.
* 점수화(목록, 점수식, 가중치식): 원본/파생 성취를 보존하면서 숫자 점수와 비음수 가중치를 만든다.
* 개수(목록): 행 수. 빈 목록은 0.
* 합계(목록, 숫자식): 각 행 값의 합. 빈 목록은 0.
* 평균(목록, 숫자식): 합계 / 행 수.
* 가중평균(목록, 숫자식, 가중치식): 합계(점수×가중치) / 합계(가중치).
* 평균의 빈 목록, 가중치 총합 0, 음수 가중치는 오류다. 기본값은 조건으로 직접 정한다.
  가중치 0인 행도 점수식은 검증/평가한다. 누락 점수를 가중치 0으로 감추지 않는다.
* 집계의 내부 합산은 반올림하지 않는다. 최종 합계/나눗셈을 소수 12자리 HALF_UP으로 반환한다.
  개별 숫자 연산 규칙과 숫자 상한은 그대로 적용한다.

==== 성취/원점수 환산

[source,text]
----
계산 환산 = 점수화(과목들,
    대응(성취, "A", 5, "B", 4, "C", 3, "D", 2, "E", 1, "F", 0),
    1
)
계산 검정고시 = 성취변경(과목들,
    구간(원점수, 99, "A", 97, "B", 93, "C", 89, "D", "E")
)
----

* 대응(값, 키, 결과, 키, 결과, ...): 정확히 일치하는 값만 찾는다. 누락 키/중복 키는 오류.
  키는 입력과 같은 숫자/문자열 타입. 결과도 모두 같은 타입이어야 한다.
* 구간(값, 하한, 결과, ..., 기본값): 하한은 숫자이며 중복 없는 엄격한 내림차순.
  처음 만족한 값 >= 하한의 결과를 사용한다. 결과와 기본값은 같은 타입이다.
* 포함(값, 후보1, 후보2, ...): 같은 타입의 후보 중 일치하는 값이 있으면 1.
* 환산 함수는 인자 전체를 평가한다. 값에 따른 지연 평가는 조건을 사용한다.
* F 규칙은 엔진에 고정하지 않았다. C 대체, 제외, 0점 포함 중 원하는 것을 코드로 선택한다.
  F를 0점으로 포함하는 것과 분모에서 제외하는 것은 서로 다른 계산이다.

==== 계산 과정과 오류

outputs는 기존 숫자 맵을 유지한다. trace는 숫자/문자열 또는 과목 행 배열이다.
행에는 original(원자료), achievement(파생 성취), score, weight가 담긴다.
원자료는 수정하지 않고 변환 단계마다 새 행을 만들므로 이전 단계 trace도 보존한다.
점수/가중치가 아직 없거나 폐기됐으면 JSON null이다.

검증은 함수/필드/인자 수/숫자·문자열·목록 타입을 검사한다.
빈 목록과 미실행 분기도 이름/타입 검증을 받지만, 중복 대응 키/구간 순서/0 나눗셈 등
값 조건은 해당 식이 평가될 때 검사한다. 미실행 경로까지 유효성을 증명하는
정책 승인 도구는 아니므로 여러 경계 샘플로 실행해야 한다.

==== 실행 가능한 예제

* current-subjects.dsl: 학교 원자료 → 학기 선택 → 국영수 F 대체/타 과목 F 제외 →
  수학 가중치 → 정보 가산 → 일반/특별 교과점수.
* ged-subjects.dsl: 검정고시 원점수 → 성취 구간 환산 → 수학 가중 평균 → 일반/특별 교과점수.
* 기존 current-school.dsl, legacy-school.dsl, ged-achievement.dsl도 유지한다.
* 합성 학교 샘플 40개 × 일반/특별, 검정고시 경계 샘플 10개 × 일반/특별의 총 100건을
  기존 Java 계산기와 소수 셋째 자리 결과로 비교한다. 실제 학생 데이터를 읽거나 저장하지 않는다.

==== 교사 피드백 후 다음 단계

. 매개변수와 수식 중 어디까지 직접 편집할지, 오류 메시지/계산 과정이 이해되는지 확인.
. 과목 코드/학기/자격증 입력을 실제 원서 모델에 연결할 계약 확정. 현재 name은 정확한 문자열 일치다.
. 학생의 학년도·불변 정책 버전 귀속 및 정책 게시/승인 절차 구현.
