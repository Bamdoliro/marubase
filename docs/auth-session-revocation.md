# 인증 세션 폐기 (#440)

선행 PR: #442. 계정당 활성 세션 하나를 유지하며, 다시 로그인하면 이전 기기의 액세스/리프레시 토큰도 폐기됩니다.

- 로그인 시 Redis에 임의 세션 ID를 TTL과 함께 저장하고 두 JWT의 sid에 넣습니다.
- 모든 인증 및 재발급 요청은 Redis의 현재 세션과 sid를 대조합니다.
- 로그아웃, 비밀번호 변경, 회원 탈퇴는 계정의 세션을 삭제합니다.
- 로그인/비밀번호 변경/로그아웃/탈퇴는 같은 User 행을 비관적 잠금으로 직렬화합니다.
- 재발급은 세션을 만들거나 연장하지 않습니다. 폐기와 겹쳐 응답된 토큰도 다음 인증에서 거부됩니다.
- Redis 장애 시 인증/재발급/비밀번호 변경/탈퇴를 성공으로 처리하지 않습니다.
- 비밀번호 변경은 세션 삭제 후 DB를 변경합니다. DB 실패 시 비밀번호는 롤백되지만 로그아웃은 유지됩니다.
- 이미 인증을 통과하여 진행 중인 요청 자체를 취소하는 기능은 아닙니다.

## 배포

DB 스키마 변경, 새 환경 변수는 없습니다. Redis auth-session:v1: 키가 생성되며 TTL은 기존 refresh-expiration-time입니다.
이전 token 키를 읽지 않으므로 기존 토큰은 사용할 수 없습니다. 전체 서버를 함께 교체하고 재로그인을 안내합니다.
롤백 시에도 현재 세션을 유지하는 방식은 지원하지 않습니다. Redis에는 인증 상태용 영속화/복구 정책을 적용하고,
과거 스냅샷 복원으로 폐기된 세션이 복구되지 않도록 복원 시 인증 세션을 무효화해야 합니다.
